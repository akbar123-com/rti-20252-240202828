# Matriks Literatur (Concept-Centric)

**Topik riset:** Analisis Perbandingan Kinerja Database MySQL vs PostgreSQL untuk Penyimpanan Data Sensor Detak Jantung Berfrekuensi Tinggi.

| # | Peneliti (Tahun) | Metode & Arsitektur | Dataset / Konteks | Hasil Utama | Celah Penelitian (Limitasi / Gap) |
|---|---|---|---|---|---|
| 1 | Salsabila et al. (2022) | IoT, Raspberry Pi, Sensor AD8232, Protokol XMPP. | Pengiriman Data Beat Per Minute (BPM). | Sistem berhasil mengirim pesan data dengan rata-rata latensi 342,857 ms dan packet loss 0. | Sistem menggunakan protokol pesan instan (XMPP) secara langsung tanpa menguji kapasitas database relasional di sisi backend untuk penyimpanan riwayat jangka panjang. |
| 2 | Ahsa et al. (2023) | Pengujian responsivitas 4 fungsi query (CRUD) pada MySQL & PostgreSQL. | Data statis aplikasi Google Playstore hingga 250.000 baris. | PostgreSQL lebih unggul karena memberikan waktu respon yang lebih cepat (selalu di bawah 4 detik). | Pengujian hanya menggunakan beban dataset statis (file Excel/CSV), belum menguji dengan aliran data (streaming) beruntun langsung dari sensor. |
| 3 | Putra et al. (2022) | Perbandingan performa respon waktu kueri CRUD pada MySQL, PostgreSQL, dan MongoDB. | Dataset permainan catur dari Kaggle sebanyak 20.058 baris data. | PostgreSQL mencatat total waktu respon tercepat (2,5 detik) dibandingkan MySQL (21,6 detik). | Hanya menguji kinerja kueri pada satu tabel menggunakan data statis, belum menerapkan percobaan pada beban data perangkat fisik IoT. |
| 4 | Lim et al. (2023) | Pengembangan alat pantau jantung *real-time* memakai Seeed XIAO BLE & MAX86150. | Data detak jantung (uji akurasi & waktu refresh). | Alat sangat akurat (tingkat eror < 0,31%) dan waktu refresh 30%-40% lebih cepat dari oximeter biasa. | Riset hanya berfokus di sisi perakitan alat (IoT) dan pengiriman nirkabel, belum membahas performa penyimpanan data di sisi database server. |
| 5 | Dachi & Suhada (2025) | Eksperimen langsung membangun database sederhana untuk membandingkan MySQL dan PostgreSQL. | Simulasi data akademik mahasiswa (NIM, Nama, Alamat). | PostgreSQL terbukti tangguh untuk data kompleks skala besar, sedangkan MySQL lebih praktis untuk proyek ringan. | Pengujian menggunakan data simulasi biasa, belum dicoba dengan data riil yang masuk terus-menerus setiap milidetik dari sensor medis. |
| 6 | Eyada et al. (2020) | Evaluasi performa manajemen data IoT di Cloud (AWS) antara MySQL vs MongoDB. | Data benchmark polusi dan stasiun cuaca IoT (1.000 record/transmission). | MongoDB (NoSQL) mengungguli MySQL saat beban sensor dan ukuran database meningkat pesat. | Literatur ini membandingkan database Relasional vs Non-Relasional (NoSQL). Belum ada komparasi head-to-head khusus sesama Relasional (MySQL vs PostgreSQL) menggunakan data sensor biologis berfrekuensi tinggi. |
